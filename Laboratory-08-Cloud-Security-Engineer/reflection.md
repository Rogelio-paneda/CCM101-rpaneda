# Mission Reflection

A host-based firewall serves as a critical secondary layer of defense by securing the individual operating system, ensuring that even if an attacker breaches the broader physical network perimeter, they still face strict access controls at the server level. This defense-in-depth approach guarantees that a compromised perimeter does not automatically result in compromised servers. Managing open network ports is directly tied to this security model because every open port is a potential entry point for unauthorized access. By intentionally closing unused ports, administrators dramatically reduce the server's attack surface, leaving fewer vulnerabilities for automated scanners and malicious actors to exploit.

In a real enterprise environment, leaving a database port like 3306 for MySQL open to the public internet is incredibly dangerous. Databases house a company's most sensitive and valuable information, and exposing them directly to the web invites automated brute-force attacks, SQL injection attempts, and data exfiltration. Databases should only ever be accessible internally via private subnets or strictly restricted IP whitelists.

Completing this mission significantly changed my perspective on how easily a server can be compromised. Seeing how quickly a newly deployed web application is exposed to the public internet without explicit firewall rules made me realize that security cannot be an afterthought; it must be built into the deployment process from the very beginning. One missed configuration can leave an entire infrastructure vulnerable in a matter of minutes.
