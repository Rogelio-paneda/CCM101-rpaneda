# Mission Reflection

**1. Which cloud infrastructure component do you think is the most important? Why?**

Of the four components I explored in this lab, I consider the operating system the most important. It serves as the interface between the applications and tools running on a server and the underlying hardware resources. Without an operating system, compute, storage, and networking resources would have no way of being managed or accessed by the software that actually delivers value to users. Everything else in the infrastructure stack depends on it functioning correctly.

**2. How does Linux support cloud computing?**

Linux supports cloud computing well because it is lightweight and efficient, making it ideal for running on virtual machines with limited resources, as I saw firsthand on my KillerCoda server. It is also easy to interact with through the terminal, allowing tasks to be automated through scripts rather than manual clicking. On top of that, Linux integrates smoothly with tools like Git, letting me manage and push my documentation directly to GitHub from the same environment I used to investigate the server.

**3. Why is technical documentation important before deploying infrastructure?**

Documentation matters because it allows other people, such as a client or a senior engineer, to understand the system without having to investigate it themselves. If findings are clearly sorted and formatted, anyone reading the report can quickly get an idea of what resources are available and how the system is set up, which saves time and avoids miscommunication before real infrastructure decisions are made.

**4. What new skills did you learn during this laboratory activity?**

I learned a lot of practical Git skills this lab, partly through trial and error. I ended up making many commits after misreading some instructions, which taught me how to recover from mistakes using commands like `git pull` and `git mv`. I also learned to work with WSL as an alternative environment, since KillerCoda kept disconnecting because of my slow home internet connection.

**5. How has your GitHub portfolio improved after completing this mission?**

My portfolio has grown noticeably since Lab 1. I now have a second structured lab folder, more meaningful commit history from working through Lab 2, and a track record of solving real Git issues, which reflects genuine hands-on experience rather than just a single successful push.
